Нужен только Python 3 (3.8+), ничего устанавливать не надо.


## HW3: семантический анализ

`python funny.py file.funny` теперь после парсера запускает проверку имён и типов и печатает
**аннотированный AST**: у каждого выражения тип после `:`, у функции — `locals` с выведенными типами.

## HW4: IR, CFG, оптимизации, граф конфликтов

```
аннотированный AST (HW3) ─► IR (funny_irgen) ─► CFG + живость (funny_cfg) ─► оптимизации (funny_opt)
                                                                            ─► граф конфликтов + раскраска (funny_regalloc)
```

Формат IR (инструкции, операнды, метки, JSON) и API для кодогенерации — **`IR.md`**.

### Флаги

| Флаг | Что делает |
|---|---|
| `--ir` | IR до и после оптимизаций, что изменил каждый проход, метрики |
| `--ir-json` | IR после оптимизаций в JSON (с `--O0` — без оптимизаций) |
| `--cfg` / `--cfg-dot` | базовые блоки, рёбра true/false, живые in/out; или то же в Graphviz DOT |
| `--interference` / `--interference-dot` | граф конфликтов и раскраска (текст / DOT) |
| `--O0` | все оптимизации выключены |
| `--opt=constprop,dce` | включить ТОЛЬКО перечисленные |
| `--disable=cse` | выключить перечисленные |
| `--config=opt.json` | то же из файла: `{"optimizations": ["constprop", "dce"], "regs": 4, "color_all": false}` |
| `--regs=K` | K регистров: узлы с цветом ≥ K — сброс (spill) |
| `--color-all` | красить и переменные программы, не только временные |
| `--run="f(1, [2, 3])"` | выполнить функцию на IR до и после оптимизаций; код выхода 1, если результаты разные |
| `--out-dir=DIR` | записать текстовые результаты: `ir_before/after.txt/.json`, `cfg.txt`, `interference.txt`, `metrics.txt/.json` |

Если указаны только настройки (`--O0`, `--opt=…`, `--disable=…`, `--regs=…`, `--config=…`, `--color-all`), печатается `--ir`.
DOT не создаётся автоматически через `--out-dir`; его можно запросить явно флагами `--cfg-dot` и
`--interference-dot`.

Оптимизации (имена для `--opt`/`--disable`):

* `constprop` — распространение и свёртка констант;
* `algebra` — алгебраические упрощения;
* `copies` — распространение копий и склейка `t := e; x := t`;
* `cse` — общие подвыражения в блоке;
* `dce` — удаление бесполезного кода;
* `unreachable` — недостижимые блоки и лишние `goto`/метки.

### Пример запуска

```
$ python funny.py tests/ir/01_constants.funny --ir

    t1 := a + 4
    b := t1
    t2 := b * 2
    c := t2
    t3 := b < 10
    if t3 goto L1
    goto L2
L1:

    ...                       (20 инструкций)
=== IR после оптимизаций (constprop, algebra, copies, cse, dce, unreachable) ===

    locals a: int, b: int, c: int
    r := x + 14
    return r
end
=== Изменения ===
calc: проходов 4; изменений: constprop 15, algebra 4, copies 6, dce 9, unreachable 4

=== Метрики ===
функция  инструкций до -> после  временных до -> после  цветов
calc     20 -> 2                 10 -> 0                0

$ python funny.py tests/ir/07_calls.funny --run="divmod(-17, 5)"
divmod(-17, 5)
    до оптимизаций:    -3, -2
    после оптимизаций: -3, -2
    совпадает
```

Готовые текстовые выходы и описания графов в формате DOT лежат в `examples/hw4/`.
Отчёт с таблицей метрик — `REPORT.md`, раздел HW4.

### Тесты HW4 (группы 9–12 в `run_tests.py`)

9. Точечные проверки оптимизаций на кусках IR (13 штук). Проверяется:
   * свёртка как в JVM;
   * что `x / 0` и `x / x` не трогаются;
   * что DCE не удаляет `load`;
   * что CSE забывает выражение после записи в операнд;
   * что константы не переходят границу блока.
10. `tests/ir/*.funny` (8 программ, 13 функций). Для каждой программы есть ожидаемые результаты в `*.cases`. IR **до и после** выполняется интерпретатором, и оба результата должны совпасть с ожидаемым (включая ошибки времени выполнения). IR до/после сверяется с эталоном `*.ir`.
11. Дифференциальное тестирование:
    * все 44 корректные программы;
    * случайные входы, в том числе `MIN`/`MAX` int и пустые массивы;
    * 13 наборов оптимизаций: все, каждая по одной, все кроме одной;
    * всего ≈ 6400 запусков, и результаты до и после совпадают.
12. Метрики и раскраска:
    * инструкций и временных после оптимизаций не больше, чем до;
    * раскраска правильная и проверена независимо по живости;
    * `--O0` не меняет IR.

## HW1. Лексер Funny на Python: регулярки → НКА → ДКА → минимальный ДКА

```sh
python lexgen.py               # шаги построения, размеры, тесты; сохраняет funny_dfa.json
python lexgen.py program.fun   # то же самое + разбивает program.fun на токены
```

### Что внутри `lexgen.py` (разделы идут по порядку алгоритма)

1. `TOKENS` — список регулярок (приоритет = порядок в списке).
2. `NFA`, `RegexParser`, `build_nfa` — регулярка → НКА (Томпсон).
3. `build_dfa` — НКА → ДКА (построение подмножеств).
4. `minimize` — минимизация Хопкрофта.
5. `match`, `lex` — как пользоваться таблицей.
6. `export_table` — запись таблицы в `funny_dfa.json`.
7. `TESTS`, `expected_single_char`, `run_tests` — тесты.

### Результат

- `funny_dfa.json` — итоговая таблица: `start`, `trap`, `tokens`, `accept[состояние]`,
  `next[состояние][байт]`.
- Размеры (после добавления токенов в HW2): НКА 305 состояний, ДКА 127, минимальный ДКА **123** (с ловушкой).
  До HW2 было 193 / 82 / 78.
- Ловушка: состояние 0. Не-ASCII байты ведут в неё из любого состояния, кроме тела комментария.
- Тесты: 120 тестов + проверка каждого из 256 байтов, на ДКА до и после минимизации.

### Добавлено в HW2

Ключевые слова `requires ensures uses int true false not and or forall exists` и символы
`->` (ARROW), `=>` (DARROW), `|` (PIPE). Без них нельзя разобрать предикаты, формулы и кванторы.
В `TOKENS` эти строки помечены «добавлено в HW2».

### Как добавить тест

Допишите строку в список `TESTS`:

```python
("match", "05", "BAD_INT"),
("lex", "if(a<=b)", "KW_IF LPAREN IDENT LE IDENT RPAREN"),
```
