ГРАММАТИКА FUNNY ДЛЯ LL(1)-ПАРСЕРА (HW2) — финальная версия
=============================================================

Обозначения (EBNF):
    "x"        терминал (токен)          IDENT, INT   терминалы-классы из лексера
    [ A ]      A можно пропустить         { A }        A ноль или больше раз
    A | B      или                        ( ... )      группировка
Каждому нетерминалу соответствует функция parse_<имя> в funny_parser.py.


1. ГРАММАТИКА
-------------

module      = { definition } EOF ;

definition  = [ "function" ] IDENT "(" [ varDef { "," varDef } ] ")" definitionTail ;
definitionTail
            = "=>" expr [ ";" ]                              (* формула *)
            | [ "requires" expr ]                            (* функция *)
              "returns" varDef { "," varDef }
              [ "ensures" expr ]
              [ "uses" localDef { "," localDef } ]
              statement ;

varDef      = IDENT ":" type ;
localDef    = IDENT [ ":" type ] ;
type        = "int" [ "[" "]" ] ;

statement   = assignment | ifStmt | whileStmt | block | assertStmt | assumeStmt ;

assignment  = IDENT assignTail ;
assignTail  = "=" expr ";"                                   (* x = e;           *)
            | "[" expr "]" "=" expr ";"                      (* a[i] = e;  сахар *)
            | "," IDENT { "," IDENT } "=" IDENT callTail ";" (* x, y = f(...);   *)

ifStmt      = "if" "(" expr ")" statement [ "else" statement ] ;
whileStmt   = "while" "(" expr ")" [ "invariant" expr ] statement ;
block       = "{" { statement } "}" ;
assertStmt  = "assert" expr ";" ;
assumeStmt  = "assume" expr ";" ;

(* Выражения: арифметика, условия и предикаты — одна грамматика, см. п. 4.1 *)
expr        = implies ;
implies     = or [ "->" implies ] ;                          (* правая ассоциативность *)
or          = and { "or" and } ;
and         = not { "and" not } ;
not         = "not" not | compare ;
compare     = sum [ relop sum ] ;                            (* не ассоциативно *)
relop       = "==" | "!=" | "<" | "<=" | ">" | ">=" ;
sum         = term { ( "+" | "-" ) term } ;
term        = unary { ( "*" | "/" ) unary } ;
unary       = "-" unary | primary ;
primary     = INT
            | "true" | "false"
            | IDENT [ callTail | "[" expr "]" ]              (* x   f(...)   a[i] *)
            | "length" callTail
            | "(" expr ")"
            | quantifier ;
callTail    = "(" [ expr { "," expr } ] ")" ;
quantifier  = ( "forall" | "exists" ) "(" varDef "|" expr ")" ;


2. ТЕРМИНАЛЫ (токены лексера, таблица funny_dfa.json из lexgen.py)
------------------------------------------------------------------

Ключевые слова:  function returns requires ensures uses while if else assert assume
                 invariant length int true false not and or forall exists
Классы:          IDENT = [A-Za-z_][A-Za-z0-9_]*     INT = 0 | [1-9][0-9]*
Операторы:       == != <= >= < > = + - * /   ->   =>   |
Разделители:     ( ) [ ] { } , ; :
Пропускаются:    пробелы, табуляции, переводы строк, комментарии // до конца строки
Ошибки лексера:  число с ведущим нулём (01) — сообщение + дальше идёт как INT;
                 недопустимый символ (@, !, не-ASCII вне комментария, в том числе "→") — сообщение,
                 символ выброшен. Алфавит — ASCII (HW1, P01, P02).


3. ПРИОРИТЕТЫ И АССОЦИАТИВНОСТЬ (от слабого к сильному)
-------------------------------------------------------

    уровень   операторы                 ассоциативность     правило
    1         ->                        правая              implies
    2         or                        левая               or
    3         and                       левая               and
    4         not  (унарный)            —                   not
    5         == != < <= > >=           нет (a<b<c — ошибка) compare
    6         + -                       левая               sum
    7         * /                       левая               term
    8         -   (унарный)             —                   unary
    9         число, имя, вызов, a[i], (...), true/false, квантор   primary

Примеры:  1 + 2 * 3        = 1 + (2 * 3)          a - b - c      = (a - b) - c
          -a * b           = (-a) * b             not x > 0      = not (x > 0)
          a and b or c     = (a and b) or c       a -> b -> c    = a -> (b -> c)


4. КАК ГРАММАТИКА ИЗ funny.ru.md ПРИВЕДЕНА К LL(1)
-------------------------------------------------

4.1. Выражения, условия и предикаты объединены в одну грамматику expr.
     Проблема: в funny.ru.md это три разных нетерминала, и все три могут начинаться с "(":
         if ((a + b) > c) ...       — "(" открывает арифметическое выражение
         if ((a > b) and c > d) ... — "(" открывает условие
     По одному токену "(" не понять, какое правило выбирать: FIRST(condition) и
     FIRST(comparison) пересекаются по "(" — это конфликт LL(1) для любого k
     (скобки могут быть вложены как угодно глубоко).
     Решение: одна лестница приоритетов, где арифметика — нижние уровни, логика — верхние.
     Отличить int от логического значения — задача семантического анализа (HW3):
     "if (r)", "assert r;", "x = a < b;" синтаксически правильны и отвергаются на этапе типов.

4.2. Устранение левой рекурсии.
     В funny.ru.md:   expr = expr "+" expr | ...   (неоднозначно и леворекурсивно).
     Сначала ввели уровни (п. 3), затем убрали левую рекурсию:
         sum = sum "+" term | term          =>   sum  = term sum'
                                                 sum' = "+" term sum' | ε
     В EBNF и в коде это цикл:  sum = term { "+" term }   (while в parse_sum).
     Левая ассоциативность сохраняется: в цикле дерево растёт влево.

4.3. Левая факторизация (общие начала правил разобраны один раз):
     - функция и формула:  обе начинаются с  IDENT "(" params ")"  — выбор после ")"
       по токену: "=>" — формула, иначе функция (definitionTail);
     - три вида присваивания начинаются с IDENT — выбор по следующему токену: "=", "[", ","
       (assignTail);
     - переменная, вызов и элемент массива начинаются с IDENT — выбор по следующему токену:
       "(", "[" или что-то другое (primary).

4.4. Висячий else — единственный конфликт LL(1).
     ifStmt = "if" "(" expr ")" statement [ "else" statement ]:
     "else" ∈ FIRST([else ...]) и "else" ∈ FOLLOW(ifStmt) (if может стоять внутри другого if).
     Разрешение (как в C/Java): else всегда относится к БЛИЖАЙШЕМУ if — парсер жадно берёт
     "else", если видит его. Пример: if (a) if (b) x=1; else x=2;   — else у внутреннего if
     (тест tests/good/04_if_else.funny, пример курса step04/good_nested_if.funny).


5. FIRST И FOLLOW (то, по чему парсер выбирает правило)
-------------------------------------------------------

FIRST(definition) = { function, IDENT }
FIRST(statement)  = { IDENT, if, while, "{", assert, assume }
FIRST(expr)       = { INT, true, false, IDENT, length, "(", forall, exists, "-", not }
FIRST(type)       = { int }

FOLLOW(statement) = FIRST(statement) ∪ { "}", else } ∪ FIRST(definition) ∪ { EOF }
FOLLOW(expr)      = { ")", "]", ";", ",", returns, uses } ∪ FIRST(statement)
                    ∪ FIRST(definition) ∪ { EOF }
                    (после requires — returns, после ensures — uses или тело,
                     после invariant — тело цикла, после формулы — следующее определение)

Проверка LL(1) для необязательных частей ([ ... ] и { ... }): токен, с которого часть
начинается, не должен входить в FOLLOW. Например:
    [ "->" implies ]:  "->" ∉ FOLLOW(implies)
    { "-" term }:      "-"  ∉ FOLLOW(sum)    (ни оператор, ни определение не начинаются с "-")
    IDENT [ "(" ... ]: "("  ∉ FOLLOW(primary) (поэтому f(x) — всегда вызов)
    formula [ ";" ]:   ";"  ∉ FOLLOW(definition) = { function, IDENT, EOF }
Единственное исключение — "else" (п. 4.4).

Ключевые клетки таблицы предсказаний:
    statement   IDENT → assignment   if → ifStmt   while → whileStmt
                "{" → block          assert → assertStmt   assume → assumeStmt
    assignTail  "=" → x = e;         "[" → a[i] = e;       "," → x, y = f(...);
    definitionTail  "=>" → формула   requires / returns → функция
    primary     INT → число   true/false   "(" → скобки   length → вызов length
                forall/exists → квантор   IDENT → имя, затем "(" вызов / "[" индекс / иначе переменная
    not         not → "not" not      иначе → compare
    unary       "-" → "-" unary      иначе → primary


6. ОБРАБОТКА ОШИБОК (режим паники)
----------------------------------

Синхронизирующие токены:
    внутри блока (оператор):  ";" (съедается)   "{" "}" if while assert assume EOF (не съедаются)
    верхний уровень:          ошибка в заголовке — пропуск до "{" (тело разбирается как обычно,
                              чтобы найти ошибки и в нём) или до ";" (конец формулы);
                              лишний токен вместо определения — пропуск до IDENT / function / EOF.
Набор для оператора — это FOLLOW(statement) плюс ";", но без IDENT и else: IDENT
встречается внутри любого выражения, и останавливаться на каждом имени значило бы
плодить каскады ошибок; else без своего if тоже не начало нового оператора.
Почему не зацикливается: каждая итерация цикла в блоке и в модуле либо разбирает
конструкцию, либо съедает хотя бы один токен (в recover_* есть явная страховка),
а токенов конечное число.


7. ОТКЛОНЕНИЯ ОТ funny.ru.md (и почему)
---------------------------------------

 1. Выражения, условия и предикаты — одна грамматика (п. 4.1). Разница int/логическое
    значение, кванторы вне предикатов, формулы вне предикатов — проверки HW3.
 2. "->" разрешено и в предикатах (в funny.ru.md оно есть только в condition), потому что
    пример курса step12/good_formulas_sorted.funny использует импликацию внутри forall.
    Сам этот пример пишет её символом "→" — это не ASCII и не терминал грамматики,
    поэтому пример даёт лексическую ошибку (расхождение примера со спецификацией).
 3. Перед функцией можно писать необязательное слово "function" (в funny.ru.md его нет,
    но оно есть в лексере HW1 и в примерах P02/P03). Перед формулой — нельзя.
 4. После формулы можно поставить ";" (в примерах курса она есть, в EBNF — нет).
 5. Индекс у массива ровно один: a[i] и a[i] = v. Записи a[i][j] и a[i][j] = v
    не поддерживаются: в Funny есть только int[], двумерных массивов не бывает,
    а arrayAccess в funny.ru.md — varName "[" expr "]" (один индекс).
 6. Приоритеты арифметики (в funny.ru.md не указаны): унарный минус сильнее * и /,
    * и / сильнее + и -, все бинарные — левоассоциативны.
 7. Сравнения не ассоциативны: a < b < c — синтаксическая ошибка с подсказкой про and.
 8. length и int — ключевые слова. length(...) разбирается как обычный вызов Call("length"),
    число аргументов проверяет семантика. int[] — три токена: int [ ] .
 9. Вызов функции как отдельный оператор ( f(x); ) запрещён — его нет в списке statement.
10. Идентификаторы могут содержать "_" (так сделано в лексере HW1).
11. Пустая программа (нет ни одной функции и формулы) — ошибка: так требует HW2.
12. Значения по умолчанию (requires = true, ensures = false, invariant = true) парсер
    в AST не подставляет: там стоит null, умолчание применяют следующие этапы.
