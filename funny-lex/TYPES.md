# HW3. Отчёт: типы, таблицы символов и ограничения

Реализация — `funny_types.py` (типы и унификация), `funny_symbols.py` (таблицы символов),
`funny_semantic.py` (проверки). Основа — `funny.ru.md` (разделы «Типы и константы», «Функции и типы»,
«Операторы», «Вывод типов локальных переменных») и P06.

## 1. Типы

| Тип | Где бывает |
|---|---|
| `int` | числа, переменные, параметры, результаты, элементы массивов, `length(a)` |
| `int[]` | массивы: переменные, параметры, результаты, `ArrayUpdate` (результат `a[i] = v`) |
| `bool` | **только** условия и предикаты: сравнения, `true`/`false`, `not`/`and`/`or`/`->`, кванторы, ссылки на формулы. Переменных, параметров и результатов типа `bool` нет (`funny.ru.md`: «отдельного типа bool для переменных нет») |
| кортеж `(int, int)` | результат функции с несколькими `returns`; можно только разложить: `x, y = f(...);` |

Служебные: `TypeVar` — «тип ещё неизвестен» (локальная без аннотации), `error` — тип выражения,
в котором уже нашли ошибку (совместим со всем, чтобы не было каскада сообщений).

## 2. Правила типов

| Конструкция | Требования | Тип результата |
|---|---|---|
| `5` | — | `int` |
| `true`, `false` | — | `bool` |
| `x` | `x` объявлена и видна здесь | тип `x` |
| `-e` | `e : int` | `int` |
| `e1 + e2`, `-`, `*`, `/` | оба `int` | `int` |
| `e1 == e2`, `!=`, `<`, `<=`, `>`, `>=` | оба `int` (массивы не сравниваются) | `bool` |
| `not p` | `p : bool` | `bool` |
| `p and q`, `or`, `->` | оба `bool` | `bool` |
| `a[i]` | `a : int[]`, `i : int` | `int` |
| `a[i] = v` → `a = ArrayUpdate(a, i, v)` | `a : int[]`, `i : int`, `v : int`, `a` — не параметр | `int[]` |
| `length(e)` | ровно 1 аргумент, `e : int[]` | `int` |
| `f(e1, ..., en)` | `f` — функция модуля, число и типы аргументов = параметрам | тип единственного `returns`; при нескольких — кортеж, допустимый только в `x, y = f(...)` |
| `p(e1, ..., en)` (формула) | только в предикатах; число и типы аргументов = параметрам | `bool` |
| `forall/exists (k:int \| P)` | только в предикатах; `k` не совпадает с видимыми именами; `P : bool` | `bool` |

| Оператор | Требования |
|---|---|
| `x = e;` | `e` не `bool` и не кортеж; `x` не параметр; тип `x` = тип `e` (новая `x` — объявляется с этим типом) |
| `x1, ..., xn = f(...);` | справа функция ровно с `n` результатами; имена слева не повторяются; ни одно не параметр; типы совпадают |
| `if (c) ...`, `while (c) ...` | `c : bool`; кванторы и формулы в `c` запрещены (условие исполняется) |
| `invariant P`, `assert P;`, `assume P;` | `P : bool` |
| `requires P` / `ensures P` | `P : bool`; `requires` видит только параметры, `ensures` — параметры и результаты |
| формула `p(...) => P` | `P : bool`, видны только параметры формулы |

## 3. Таблицы символов и области видимости

```
модуль:   функции и формулы (Signature)           — собираются ДО проверки тел:
                                                    работают рекурсия и вызов функции, объявленной ниже
функция:  параметры  →  возвращаемые значения  →  локальные (uses + первые присваивания)
             ↑ requires        ↑ ensures              ↑ тело, invariant, assert, assume
квантор:  своя область с переменной квантора, внутри предиката
```

- **Повторное объявление** — ошибка, если имя уже видно: два параметра `a`, параметр и результат с одним
  именем, `uses` с именем параметра, переменная квантора с именем параметра/локальной, две функции/формулы
  с одним именем, одна переменная дважды слева в `x, x = f()`.
- **Использование до объявления**: локальная объявляется первым присваиванием в порядке текста программы
  (или в `uses`). Чтение раньше — ошибка «используется до первого присваивания».
  Блоки `{ }` и ветки `if` новых областей не создают: переменная из ветки видна после `if`
  (в Funny нет объявлений внутри блоков). Чтение объявленной, но ещё не получившей значение переменной
  (`uses x` или ветка `if`, которая не выполнилась) — не ошибка: по `funny.ru.md` его результат неопределён.
- Функции и переменные — **разные пространства имён**: `f(x)` ищется среди функций, `x` — среди переменных.
  Локальная `divmod` не мешает функции `divmod` (тест `types_good/03_calls`). Перепутать их — понятная ошибка:
  «'helper' — функция, а не переменная», «'r' — переменная, а не функция».
- **Параметры только для чтения** (требование T1 проекта): `x = ...`, `a[i] = ...` и `x, y = f()` с параметром
  слева — ошибка. Возвращаемые значения и локальные писать можно.

## 4. Вывод типов локальных (бонус)

Локальная переменная без аннотации получает **переменную типа** (`TypeVar`). Первое присваивание
**унифицирует** её с типом значения — и тип становится известен. Дальше каждое использование тоже
унифицирует: несовпадение = ошибка.

```
uses t, m:int;        t : ?t       m : int
t = a;                ?t := int[]                    (a : int[])
m = t[0];             t[...] требует int[] — ok;  m : int = int — ok
x = 1;                новая x : ?x := int
x = a;                int ≠ int[]  →  «нельзя присвоить int[] переменной 'x' типа int»
uses never;           ни одного присваивания → ?never так и не стал известен
                      →  «не удалось вывести тип локальной переменной 'never'»
```

Унификация — упрощённая Хиндли–Милнера для мономорфных типов: `?a` связывается с конкретным типом
или с другой `?b` (`uses a, b; a = b;` — обе останутся неизвестными, если дальше ничего не уточнит).
Если значение содержит ошибку (тип `error`), переменная тоже получает `error` — без второго сообщения.
Итоговые типы локальных записываются в `Function.locals` (печать: `python funny.py file.funny --symbols`).

## 5. Диагностика

- Позиция — у узла AST (строка:столбец из лексера), формат как в HW2: `файл:строка:столбец: ошибка: текст`.
- Сообщение говорит, что ожидалось и что получено: `индекс массива: ожидался тип int, а здесь int[]`.
- Анализ не останавливается на первой ошибке; повторы подавляются: о неизвестном имени — один раз
  на функцию, одинаковые сообщения в одной позиции — один раз, выражение с ошибкой имеет тип `error`.
- Если есть синтаксические ошибки, семантический анализ не запускается (дерево неполное).

## 6. Ограничения и решения

1. Нет `bool`-переменных, нет приведений и перегрузок — в Funny их нет. Пункт HW3 про `string/func`
   к Funny не относится: типы — `int`, `int[]`, логические условия и кортежи результатов.
2. Сравнивать можно только `int`: `a == b` для массивов — ошибка (`funny.ru.md`: «сравнения требуют int»).
3. Функции можно вызывать и внутри предикатов (это обычные выражения); формулы и кванторы — только в предикатах.
4. Не проверяется: что возвращаемым значениям что-то присвоено и что переменная проинициализирована на
   всех путях (чтение неинициализированной по спецификации неопределено, а не ошибка) — это задача
   анализа потока данных (HW4).
5. Тип `uses x` без присваиваний вывести нельзя даже если `x` только читается — это ошибка «не удалось вывести тип».
